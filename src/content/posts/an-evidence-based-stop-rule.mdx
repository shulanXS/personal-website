A traveler asks whether a particular Sunday ferry will get them to a museum's accessible entrance by 10:00. A search agent turns up a timetable, an opening-hours page and two copies of a visitor guide. It has four documents. Does it have an answer? I would put the documents aside for a moment and write down what would have to be true for the traveler to make that trip.

A retrieval agent needs two stopping rules. A resource rule limits elapsed time, tokens or tool calls. An evidence rule determines whether the observations support an answer. I keep them separate because exhausting five searches is a fact about the run. It says nothing about whether the requested condition holds.

For a conjunctive question, decompose the proposed answer into necessary claims. Give each claim a status, a scope and references to the observations that support it. A claim about Sunday opening hours needs evidence that applies to that location, entrance and date. A second copy of an undated page may improve retrieval confidence without resolving any of those qualifiers. HALT takes a verification-oriented approach to stopping retrieval agents. [HALT, Findings of EMNLP 2026](https://aclanthology.org/2026.findings-emnlp.343/)

## Turn the itinerary into a small proof obligation

Suppose the timetable is valid for the travel date and gives a 09:35 arrival. A published route from the dock takes 20 minutes to the east entrance. Under those assumptions arrival is 09:55, leaving five minutes of margin. A museum page says the *building* opens at 09:00. The arithmetic is now settled, but there is still no evidence that the east entrance is accessible and open that morning. The front door and the step-free door may operate on different schedules.

```text
candidate    Sunday sailing → dock → east entrance
supported    sailing runs on the specified date       [timetable, revision A]
supported    09:35 + 20 minutes = 09:55                [route estimate, east]
open         east entrance admits this visitor by 10   [no dated observation]
```

An important assumption is easy to miss in even this small record. A 20-minute transfer estimate is evidence for a *scheduled* itinerary under the stated mobility and walking assumptions. It cannot guarantee an actual ferry arrival or a particular person's transfer time. If the question asks about a guaranteed connection, the proof obligation changes. I would carry that distinction into the answer rather than turn a five-minute scheduled margin into a promise.

## Implement the decision independently of the search policy

```python
def decide(claims, calls_left):
    if not claims:
        raise ValueError("define the required claims first")
    if "refuted" in claims:
        return "candidate_blocked"
    if all(status == "supported" for status in claims):
        return "candidate_verified"
    if calls_left == 0:
        return "unresolved"
    return "retrieve"

print(decide(["supported", "unknown"], 0))
print(decide(["supported", "refuted"], 0))
# unresolved
# candidate_blocked
```

Here the inputs are already adjudicated. Contradictory sources require a scope and freshness check before a verifier assigns `refuted`. An unresolved contradiction stays open. The ordering makes a detail explicit: the last permitted call can still resolve the question. Evaluate its evidence before reporting budget exhaustion.

Now change just the final observation. A dated notice says the east entrance will be closed until 11:00. The correct status of this candidate is blocked even if five lookups remain. Next, replace the notice with a page that does not mention the east entrance. Its absence from the page supplies no dated closure. The candidate stays open, and the next useful query can be narrowly about access through that entrance. Spending another call on the ferry timetable would increase cost while leaving the only open condition untouched.

The four strings returned by the function are intended for a caller. Only the verified state licenses a positive answer for this candidate. A blocked state can lead the planner to another entrance. A retrieve state requests more work on an open condition. An unresolved state returns control to the user with the missing condition intact. Treating every terminal state as “ready to answer yes or no” would undo the careful verification inside the function.

## Candidate scope changes the conclusion

A Sunday itinerary can require a particular ferry, enough transfer time and an accessible entrance by 10:00. A date-specific closure notice refutes the entrance condition for that candidate. It establishes that this itinerary fails. It establishes global infeasibility only if the closure applies to **all** allowable itineraries or the search has covered them exhaustively. That difference between a conjunction within one candidate and a choice among candidates is easy to lose in a natural-language summary.

When several candidates remain, I retain the open claim that would change the decision and use it to choose the next retrieval. If the agent repeatedly fetches the same document revision, the record shows identical evidence IDs and no change in coverage. That is a reason to reformulate the query, use another source or return an unresolved answer. It is never positive evidence that a missing fact is false.

For evaluation, I would pair answer accuracy with excess calls *after* sufficient evidence was available, and count premature terminal answers separately. A policy can improve its average call count simply by giving up early. The failure that matters to the application is turning “budget exhausted” into a definite answer.

I would grade this with a paired example. In one run the final allowed call supplies a dated opening notice. In the other it supplies a duplicate of the generic visitor page. A fixed-depth search makes the same number of calls in both runs; an evidence-sensitive policy reaches different conclusions. The first can report the scheduled 09:55 arrival and cite access through the east entrance. The second can report the sailing and projected arrival while explicitly leaving entrance access unverified.

For a reader planning a trip, that partial answer has real value. It says which fact to check by phone and which parts of the plan already have evidence. For an engineer, it gives the next experiment a target. If most unresolved cases lack entrance-specific hours, improving access to that source may pay off more than raising the global call budget.
