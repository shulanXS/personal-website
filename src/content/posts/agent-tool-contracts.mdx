A tool call can be structurally valid and still be wrong to execute. A string is a valid `path`; it might nevertheless point outside the authorized workspace. A well-formed ticket request may duplicate a ticket created by an earlier timed-out call.

Tool integration needs a contract that extends beyond the function signature. The contract must describe permitted inputs, permitted effects, observable outcomes, and recovery behavior.

## Table of contents

## Distinguish protocol from application policy

The [MCP tools specification dated 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) defines mechanisms for describing tools and returning results. This article uses that specific version as a reference rather than assuming every client implements later protocol changes.

An input schema helps reject the wrong shape of request. It does not determine which files the current user authorized, whether a network destination is acceptable, or whether a write should be repeated. Those decisions belong to the application and its execution environment.

For a repository-reading task, a narrowly scoped `read_repository_text` tool is easier to constrain than an unrestricted shell. This does not make general shell access inherently unusable; it means the policy surface is larger and must be designed accordingly.

## Specify behavior before writing the adapter

An application-level contract could be:

<ResponsiveTable>

| Condition | Required behavior |
| --- | --- |
| Relative path to an allowed UTF-8 text file | Return bounded text |
| Absolute path or resolved path outside the root | Reject |
| Directory, oversized file, or invalid encoding | Return a stable error code |
| Permission failure or missing file | Report a distinguishable failure |
| Unexpected internal error | Record restricted diagnostics and return a trace identifier |

</ResponsiveTable>

The root must come from trusted task configuration, not from an argument the model can freely replace. Even within that root, a production system may need an allowlist excluding credentials, personal data, and unrelated project material.

## A runnable reader with explicit limits

Save this example as `reader.py` and run it with Python 3.11 or later. It assumes a trusted root and no adversarial concurrent filesystem modifications.

```python
from pathlib import Path
from tempfile import TemporaryDirectory


class ToolError(Exception):
    pass


def read_text(root: Path, relative: str, limit: int = 65536) -> str:
    if limit < 1:
        raise ValueError("limit must be positive")
    if not relative or Path(relative).is_absolute():
        raise ToolError("expected_relative_path")
    try:
        base = root.resolve(strict=True)
        target = (base / relative).resolve(strict=True)
        if not target.is_relative_to(base):
            raise ToolError("outside_workspace")
        if not target.is_file():
            raise ToolError("expected_regular_file")
        with target.open("rb") as stream:
            data = stream.read(limit + 1)
        if len(data) > limit:
            raise ToolError("file_too_large")
        return data.decode("utf-8")
    except FileNotFoundError as error:
        raise ToolError("not_found") from error
    except PermissionError as error:
        raise ToolError("permission_denied") from error
    except UnicodeDecodeError as error:
        raise ToolError("invalid_utf8") from error


if __name__ == "__main__":
    with TemporaryDirectory() as directory:
        parent = Path(directory)
        root = parent / "repo"
        root.mkdir()
        (root / "note.txt").write_text("hello", encoding="utf-8")
        (parent / "private.txt").write_text("private", encoding="utf-8")
        assert read_text(root, "note.txt") == "hello"
        cases = [("../private.txt", 100, "outside_workspace"),
                 ("missing.txt", 100, "not_found"),
                 ("note.txt", 2, "file_too_large")]
        for name, limit, expected in cases:
            try:
                read_text(root, name, limit)
            except ToolError as error:
                assert str(error) == expected
            else:
                raise AssertionError(f"accepted {name}")
    print("reader checks passed")
```

Reading `limit + 1` bytes makes the size check meaningful without loading the whole file. Returning an error rather than a silent partial string prevents the model from assuming it saw a complete document. An alternative interface can support excerpts, but must label them as incomplete and provide continuation metadata.

## Understand the remaining filesystem risks

Resolving a path before checking containment handles ordinary traversal and symlinks that resolve outside the root. It does not remove the race between checking and opening. Another process could replace a path during that interval. The ordinary-file check also cannot serve as isolation against a hostile concurrent filesystem.

For adversarial workloads, use a suitably isolated filesystem and OS-specific mechanisms that constrain traversal and opening, rather than treating this portable snippet as a sandbox. The sample also leaves other `OSError` subclasses and unusual symlink failures to propagate. A production adapter should map these to internal failures, preserve a trace, and avoid exposing raw exception chains containing sensitive paths.

This is why the assumptions are part of the tool contract. Code that is appropriate for a trusted local repository may be inappropriate for a shared worker processing attacker-controlled trees.

## Model errors and transport errors need different responses

If the argument is invalid, the model can revise it. If authorization fails, retrying the same request should not grant access. If a read times out, retry may be acceptable after a bounded backoff.

A remote write is different. A timeout may mean the effect happened but the response was lost. Retry only when the service's idempotency or reconciliation mechanism makes repetition safe. See [the recovery protocol for interrupted runs](/posts/agent-harness-checkpoints/) for the ambiguous-outcome case.

Do not let a server-supplied “retryable” flag override local permissions or the side-effect policy. The harness should combine transport state, tool semantics, and task authorization before scheduling another attempt.

## Test both successful and rejected requests

Extend the included checks with absolute paths, invalid UTF-8, directories, symlinks to outside files, and permission failures on the target operating system. Test adapter-level schema failures separately from execution errors. For write tools, add duplicate requests and lost-response simulations.

A good description makes correct use easier for the model. Enforced execution boundaries make incorrect use less damaging. Both are necessary, and neither can stand in for the other.
